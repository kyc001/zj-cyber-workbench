# 项目需求分析

## 一、项目背景

网络安全教学、授权测试和日常运维诊断通常需要同时使用多类工具：资产探测、漏洞验证、代码审计、知识整理、报告编写、远程主机操作和证据留存。传统做法依赖多个终端、脚本和零散文档，操作成本高，过程难复现，也不利于教学演示。

本项目希望实现一个统一的桌面工作台，把多 Agent 协作、受控命令执行、SSH 工作区、Toolpack 工具箱、知识库和 Skill 扩展整合在一个界面中，降低使用门槛，同时保留安全边界和审计能力。

## 二、目标用户

- 课程实践小组：用于展示安全运维工作台的设计、实现和测试成果。
- CTF 与安全教学场景：用于演示多 Agent 分析、工具调用和报告整理流程。
- 授权安全测试人员：在明确授权范围内进行资产检查、信息收集和漏洞验证。
- 运维人员：对主机、端口、DNS、TLS、HTTP 状态和远程文件进行诊断。

## 三、核心需求

### 1. 桌面端集成

项目需要以 Windows 桌面应用形式交付。用户启动 Electron 应用后，桌面壳负责启动 Python sidecar，自动寻找可用本机端口，并加载 React 工作台页面。打包后用户不需要手动启动后端服务。

### 2. 多 Agent 工作台

系统需要提供 Playground 页面，允许用户创建会话、选择 Agent、发送文本和文件输入、查看流式回复、观察子 Agent 协作过程，并下载分析报告。Agent 需要能够根据当前执行工作区调用工具。

### 3. 受控执行工作区

系统需要支持本机工作区和 SSH 工作区。本机工作区用于 Windows portable tools 和受控 PowerShell 动作；SSH 工作区用于 Linux 侧工具和远程运维。所有命令执行、文件读写和取消操作都需要经过统一服务层。

### 4. Toolpack 工具箱

系统需要提供结构化工具清单、参数表单、执行策略、运行状态、取消能力、结构化结果和 artifact 下载。工具包括 HTTP、DNS、TLS、端口、目录扫描、资产发现等低风险诊断和安全测试能力。

### 5. 主机与权限管理

系统需要提供主机登记、SSH 连接信息管理、host key 信任、运行权限和系统用户等管理能力。Agent 不应绕过用户授权自动信任变化后的 host key。

### 6. 知识库与项目管理

系统需要支持知识资源、文档处理、项目资产、发现项和关系图展示。Agent 和用户可以围绕具体项目组织证据、上下文和报告。

### 7. Skill 扩展与 Skill Hub

系统需要支持 Skill 包安装和管理。独立 Skill Hub 负责用户注册、命名空间、Skill 发布、浏览、评分、下载和审计；工作台侧负责下载后校验和安装。

### 8. 发布与测试

系统需要支持开发环境检查、依赖安装、单元测试、类型检查、前端构建、PyInstaller sidecar 构建和 Electron Windows 打包。发布产物需要有 checksum 和 build manifest。

## 四、非功能需求

- 安全性：命令、文件和 SSH 操作必须受权限和路径校验限制。
- 可维护性：前后端通过 OpenAPI 和 typed client 对齐接口。
- 可扩展性：Agent、Toolpack、Skill 和 Skill Hub 都应以模块化方式扩展。
- 易用性：工作台首页直接进入可操作界面，不设置纯说明型入口页。
- 本地优先：开发数据使用 `.zj/`，桌面运行数据使用用户本地数据目录。
- 可验证性：核心服务、Toolpack、权限、Skill Hub、桌面会话和前端页面均需要测试覆盖。

## 五、约束条件

- 项目面向授权安全测试和教学，不支持未授权攻击行为。
- Windows 10/11 x64 是主要交付平台。
- 后端 sidecar 只绑定 loopback 地址。
- SQLite 是默认本地持久化方案。
- 打包产物不应包含开发环境密钥、运行数据库、日志或历史 artifact。
