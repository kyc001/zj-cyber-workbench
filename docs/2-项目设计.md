# 项目设计

## 一、总体架构

项目采用桌面壳、前端工作台、Python 后端和独立 Skill Hub 的组合架构。

```text
Electron Desktop
  -> 启动 Python sidecar
  -> 加载 React 工作台

React Workbench
  -> /api 调用 FastAPI 后端
  -> WebSocket/SSE 获取 Agent 流式事件

FastAPI Backend
  -> Agent Runtime
  -> Sandbox/Workspace
  -> Host/SSH/SFTP
  -> Toolpack
  -> Knowledge/Work Project
  -> Skill Hub client
  -> SQLite

Skill Hub
  -> 独立 FastAPI 服务
  -> 独立 React 前端
  -> Skill ZIP 校验、存储和下载
```

## 二、后端设计

后端入口为 `app.py` 和 `main.py`。`main.py` 加载配置、初始化日志并启动 uvicorn；`app.py` 创建 FastAPI 应用，注册中间件、异常处理、业务路由和前端静态资源。

主要模块：

- `core/`：Agent Runtime、模型接入、上下文、子代理、工具注册和安全控制。
- `service/`：业务服务层，负责 Agent 会话、工作区、工具箱、主机、知识库、项目、用户和 Skill Hub 安装。
- `router/`：FastAPI 路由定义。
- `handler/`：请求处理和服务编排。
- `schema/`：接口数据结构。
- `model/`：SQLite 数据模型。

应用启动时会初始化数据库、创建本地桌面用户、确保默认本机工作区、启动 LightRAG、知识文档处理、异步命令运行时、子 Agent runtime、报告清理和工作区状态监控。

## 三、Agent 设计

Agent 角色在 `core/agent/specs.py` 和 `core/agent/registry.py` 中定义。系统内置多个 Agent 角色：

- `cso`：安全协调与任务编排。
- `cae`：代码审计。
- `cce`：密码与协议分析。
- `cie`：情报侦察。
- `cpe`：安全测试。
- `cre`：逆向分析。

Agent 会话由 `service/agent/runtime.py` 和 `core/runtime/session.py` 管理。系统支持会话池、流式事件、子代理任务、上下文压缩、报告生成、任务中断和取消。

## 四、执行工作区设计

执行工作区由 `service/sandbox/` 提供统一抽象，并覆盖两类场景：

- 本机工作区：面向 Windows portable tools、受控 PowerShell 动作和本地文件操作。
- SSH 工作区：面向 Linux 主机命令、SFTP 和 Linux 工具。

文件操作由服务层做路径归一化和越界防护；长时间命令通过异步任务保存输出，并支持取消。工作区状态会被后端监控，并同步给前端 Playground、Container Shell 和 Toolpack。

## 五、Toolpack 设计

Toolpack 由 `service/toolpack.py`、`router/toolpack.py` 和 `schema/toolpack.py` 组成。每个工具都有结构化 manifest，包括：

- 工具 ID、名称、描述和分类。
- backend 类型：本机或 SSH。
- 输入 schema。
- 默认超时和最大超时。
- 策略限制，例如最大并发、最大 RPS、端口数量和 FUZZ 标记要求。
- 执行结果和 artifact。

Toolpack 不直接开放任意命令，而是把用户参数转为受控命令，再通过工作区执行路径运行。

## 六、前端设计

主工作台位于 `web/`，使用 React、TypeScript 和 Vite。路由由 `web/src/app/App.tsx` 组织，主要页面包括：

- Playground：多 Agent 会话和执行工作区入口。
- Hosts：主机和 SSH 连接管理。
- Egress Proxies：出口代理管理。
- Knowledges：知识库管理。
- Work Projects：项目资产和图谱。
- Sandbox Images / Sandbox Containers：工作区管理。
- Toolpack：结构化工具箱。
- Skill Hub：Skill 浏览和安装入口。
- System Users / System Config：用户和系统配置。

前端通过 `web/openapi.json` 和 `web/src/shared/api/generated/schema.ts` 保持接口类型一致。

## 七、桌面端设计

桌面端位于 `desktop/`。Electron 主进程负责：

- 单实例锁。
- splash 启动页。
- CSP 和导航策略。
- 启动 Python sidecar。
- 分配 loopback 端口。
- 设置运行数据目录。
- 加载 React 工作台。
- 应用退出时停止 sidecar。

开发模式可以连接 Vite 和源码后端；打包模式从 Electron resources 中加载 PyInstaller 生成的 `zj-core.exe`。

## 八、Skill Hub 设计

Skill Hub 是独立注册中心，后端位于 `skill_hub/`，前端位于 `skillhub-web/`。它负责：

- 用户注册和登录。
- 命名空间管理。
- Skill 包发布。
- ZIP 包结构校验。
- Skill 列表、详情、下载、收藏和评分。
- 审计日志。
- 可选 Redis 限流。

Skill Hub 只校验和存储包内容，不执行包内容。工作台侧下载后再校验并安装到本地 Skill 目录。

## 九、安全设计

- 后端只绑定 loopback 地址。
- 本机 PowerShell 只走受控动作。
- SSH host key 需要显式信任。
- 文件读写必须做路径越界检查。
- Toolpack 参数必须先经过 schema 和策略校验。
- Agent 工具受当前工作区、权限模式和审批机制约束。
- 配置、密钥、数据库、日志和 artifact 不进入发布输入。
